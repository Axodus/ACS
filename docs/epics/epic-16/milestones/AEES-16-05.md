# AEES-16-05 — Provider Boundary & Capability Contract

Status: IN PROGRESS
Type: execution + acceptance
Canonical UI: .design/app-standalone
/static: forbidden

AEES-16-05 S01 defines the canonical provider boundary for ACS production financial operations. It makes provider identity, provider mode, capability, eligibility and readiness explicit without introducing broad provider orchestration.

## Canonical environment/provider topology

| Environment | Dispatch | OpenClaw Worker | Provider boundary |
| --- | --- | --- | --- |
| LOCAL | local | OpenClaw Worker — Local | localhost and local providers are allowed |
| DEVELOPMENT | remote | OpenClaw Worker — Cloud | Vercel acs-app + Railway Product API + Cloud worker |
| PRODUCTION | remote | OpenClaw Worker — Remote VM | dedicated services / VMs + durable providers |

## Guardrails

- Do not implement provider orchestration, failover or retry policy in S01.
- Do not expose secrets, bearer tokens or credential material in diagnostics.
- Do not touch /static.
- Do not silently fall back from cloud / remote / production providers to local substitutes.
- Keep truth in the control-plane read model; do not duplicate competing contracts.
