## S01 normative invariants

The ACS Account is global. Tenant membership and roles remain separate authoritative records keyed by `principalId = accountId`. A verified unknown wallet identity creates an Account without Tenant membership.

For EVM identities:

```text
namespace = eip155
normalizedAddress = lowercase 0x-prefixed 20-byte address
subject = reown_siwx:eip155:<normalizedAddress>
caip10 = eip155:<chainId>:<normalizedAddress>
```

Identity uniqueness is `provider + namespace + subject`. The subject is chain-agnostic so Base Sepolia and Ethereum Sepolia resolve the same ACS identity while CAIP-10 records the chain actually verified.

ACS session tokens must have at least 256 bits of entropy. Persist only a cryptographic digest, compare digests in constant time, record explicit `expiresAt` and `revokedAt`, and never extend the fixed 15-minute TTL through `lastSeenAt`.

Suspension is immediate: existing ACS sessions become unusable, new exchange is rejected, wallet connection may remain alive, and Tenant/role/financial authority remains unavailable.

## S02 hard gate

`SiwxAuthenticatedArtifactVerifier` accepts only the nonce/message/signature/session structure that the selected Reown/SIWX integration can officially validate server-side and derives the verified identity independently from the browser.

The Product API must never set `trusted=true` from wallet connection, a browser-provided address or client-only signature verification. The endpoint may adapt its request shape to the official integration without changing this security boundary.

## S02 delivered implementation

The official custom Reown AppKit/SIWX design is implemented: AppKit obtains an ACS nonce, signs the SIWX message, and the Product API validates the message/signature independently with `viem`, including the approved RPC path used by smart-account signature verification.

The canonical standalone now includes Reown AppKit, the wagmi adapter, required SIWX, Base Sepolia and Ethereum Sepolia network selection, Product API nonce/exchange, typed ACS session storage and a bounded account control. Wallet-only state is rendered separately from ACS-authenticated state. The browser sends only the selected verifier request shape (`message` and `signature`); the Product API derives address, chain, subject, CAIP-10 and verification timestamps from the server-verified proof.

The server verifier is explicitly enabled with `ACS_SIWX_VERIFIER_ENABLED=true`, requires an origin allowlist and approved chain RPC URLs, and requires `ACS_SHARED_DATABASE_URL` outside LOCAL. When those values are absent the exchange remains fail-closed with `SIWX_VERIFIER_NOT_CONFIGURED`; HTTP readiness is unaffected.
