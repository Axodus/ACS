# REQ-03 Native Contract Specification

## 1. Contract rules

All canonical records are ACS-owned, provider-neutral, domain-scoped, and
versioned. External systems can supply observations, proposals, or execution
results, but they cannot define ACS identity, authority, workflow history, or
institutional evidence.

Canonical records use references for credentials, secrets, artifacts, policies,
knowledge, tools, providers, models, harnesses, executors, engines, targets,
and workers. Values such as API keys, access tokens, private keys, raw secret
material, or provider session credentials are never embedded.

Every record that can affect reproducibility carries:

```text
organization_id
product_domain
owner_ref
authority_scope_ref
revision_or_snapshot_ref
created_at
created_by
```

`tenant_id` remains accepted as compatibility vocabulary for the current ACS
implementation. New user-facing documentation uses `organization_id`.

## 2. Shared primitives

```yaml
EntityRef:
  kind: string
  id: string
  revision: integer?

Scope:
  organization_id: string
  product_domain: string
  tenant_id: string?
  owner_ref: string
  authority_scope_ref: string
  knowledge_scope_refs: [string]
  budget_scope_ref: string?
  credential_scope_ref: string?

RevisionRef:
  entity_kind: agent | workforce | workflow | policy | resource | schema
  entity_id: string
  revision: integer
  fingerprint: sha256

PolicySnapshotRef:
  policy_id: string
  revision: integer
  fingerprint: sha256
  decision_context_hash: sha256

Idempotency:
  key: string
  scope: string
  request_hash: sha256
```

IDs are opaque strings. They are generated by ACS, stable for the life of the
record, and never derived from provider IDs. A revision fingerprint covers the
canonical normalized content and excludes timestamps that do not change
meaning.

## 3. Versioning strategy

Definitions use stable identity plus immutable integer revisions. Contracts,
events, schemas, and APIs use an explicit major/minor schema version:

| Surface | Version rule | Compatibility rule |
|---|---|---|
| Agent/Workforce/Workflow definition | Stable ID plus monotonic revision and content fingerprint | Old revisions remain readable and are never edited in place. |
| Contract schema | `major.minor` | Minor versions add backward-compatible fields; major versions require an explicit mapper and migration decision. |
| Event schema | `event_type` plus `schema_version` | Consumers must tolerate additive fields and reject incompatible major versions safely. |
| API | `/api/v1` compatibility and additive `/api/v2` | v1 remains readable during migration; v2 commands are idempotent and versioned independently. |
| Execution run | Immutable references to exact definition, policy, binding, and economic snapshots | Historical runs remain reproducible from stored references even after current definitions advance. |

Canonical payloads use explicit `revision`, `fingerprint`, `schema_version`,
and `created_at` fields where applicable. A migration mapper must declare its
source version, target version, lossiness, and evidence record. No compatibility
mapper may silently replace a historical reference.

### Contract

```yaml
  ref: RevisionRef

  role_ref: EntityRef?
  instructions: string
  capability_requirements: [EntityRef]
  constraints: [EntityRef]
  knowledge:
    allowed_scope_refs: [string]
    denied_scope_refs: [string]
    context_policy_ref: RevisionRef
    memory_policy_ref: RevisionRef
  resources:
    skill_refs: [RevisionRef]
    tool_refs: [RevisionRef]
    mcp_server_refs: [RevisionRef]
  runtime_preferences:
    provider_routes: [EntityRef]
    model_requirements: [EntityRef]
    harness_preferences: [EntityRef]
    executor_preferences: [EntityRef]
  governance:
    authority_refs: [EntityRef]
    permission_policy_ref: RevisionRef
    approval_policy_ref: RevisionRef
  economics:
    cost_policy_ref: RevisionRef
    budget_policy_ref: RevisionRef
    settlement_policy_ref: RevisionRef?
  evidence:
    audit_policy_ref: RevisionRef
    evaluation_refs: [EntityRef]
  commit:
    created_by: string
    committed_at: timestamp
    change_reason: string
```

### Invariants

- Agent identity is not a model, provider, executor, harness, runtime process,
  workforce slot, or external provider ID.
- A committed revision is immutable. Change creates a new revision and retains
  the predecessor reference.
- A run resolves the revision into an `ExecutionBinding`; it never mutates the
  historical revision.
- Credentials are represented only by connection or lease references.
- Sharing an agent does not share memory, knowledge, credentials, budget,
  evidence, or authority without an explicit grant.
- Existing ACS fingerprinting and optimistic revision controls remain the
  compatibility foundation; durable no-update/delete lineage tests are required
  before marking the repository implementation complete.

**Decision:** `FROZEN-v1` semantic contract; implementation completion is Phase 1.

the current repository lacks a durable canonical Workforce aggregate and run
membership store.

The graph revision is immutable. Dynamic orchestration can emit a
`GraphAmendmentProposal` with a base fingerprint and typed operations. ACS
accepts, modifies, or rejects it using compare-and-swap validation. A planner
cannot mutate a leased, running, completed, or approved task in place.

**Decision:** `PARTIAL` as an implementation surface; the graph contract is
stable enough for Phase 3 design and validators, but current ACS still exposes
linear workflow primitives.

## 9. Executor contract

The executor-neutral interface has mandatory and capability-dependent operations.

| Operation | Requirement | Semantics |
|---|---|---|
| `capabilities` | mandatory | Advertise supported operations and limits. |
| `submit` | mandatory | Accept an idempotent request or return a typed rejection. |
| `status` | mandatory | Return normalized state for a known execution handle. |
| `result` | mandatory | Return terminal result or explicit `unknown`. |
| `stream` | capability-dependent | Emit ordered observations with cursor and event IDs. |
| `cancel` | capability-dependent | Request cancellation; unsupported must be explicit. |
| `resume` | capability-dependent | Resume only from a declared checkpoint/recovery handle. |
| `timeout` | mandatory policy | ACS deadline governs admission; executor reports timeout observation. |
| `artifacts` | mandatory result field | Return references and digests, never unbounded opaque payloads. |
| `usage` | mandatory result field | Return normalized usage when measurable; missing data is explicit. |
| `failure` | mandatory | Return normalized category, retryability, and safe detail. |

Conceptual interface:

```typescript
interface Executor {
  capabilities(): Promise<ExecutorCapabilities>;
  submit(request: ExecutionRequest): Promise<ExecutionHandle>;
  status(handle: ExecutionHandle): Promise<ExecutionStatus>;
  result(handle: ExecutionHandle): Promise<ExecutionResult>;
  stream?(handle: ExecutionHandle, cursor?: string): AsyncIterable<ExecutionEvent>;
  cancel?(handle: ExecutionHandle, reason: string): Promise<CancelResult>;
  resume?(request: ResumeRequest): Promise<ExecutionHandle>;
}
```

Codex, OpenClaw, direct-model, HTTP/job, sandbox, and human approval adapters
may implement this interface. The adapter never owns Agent identity,
Workforce composition, institutional authority, canonical evidence, or cost
allocation.

**Decision:** `FROZEN-v1` semantic contract; adapters remain separately
authorized implementation work.

```yaml
  created_at: timestamp
  started_at: timestamp?
  completed_at: timestamp?
```

Leases, fencing, idempotency, recovery and resume are compatibility
requirements. A retry revalidates failure class, deadline, authority,
approval, budget/reservation, and binding. An unknown external outcome must be
reconciled before retry. Resume is a newly admitted operation from a durable
checkpoint; it is not silent requeueing.

**Decision:** `FROZEN-v1` lifecycle semantics.

## 14. Product API contract

Products use ACS-native asynchronous operations. Commands return an accepted
request/run reference; reads return current projections with event cursors.

| Operation | Proposed v2 semantic | Default mode |
|---|---|---|
| Create/run agent | Resolve revision, policy, binding, and create a Run | asynchronous |
| Create/run workforce | Freeze membership and create a Workforce Run | asynchronous |
| Run workflow | Validate graph and create a Workflow Run | asynchronous |
| Get run/task | Return current state, refs, blockers, and last event cursor | synchronous read |
| Stream run | Return ordered ACS events after a cursor | streaming |
| Approve/reject | Record an ApprovalDecision with idempotency | synchronous command |
| Cancel | Request cancellation under policy and emit outcome | asynchronous |
| Resume | Admit from a named checkpoint after revalidation | asynchronous |
| Get artifacts/evidence | Return references and redacted metadata | synchronous read |
| Get usage/cost | Return normalized records and calculation status | synchronous read |

Illustrative routes remain under ACS ownership:

```text
POST /api/v2/executions
GET  /api/v2/executions/{runId}
GET  /api/v2/executions/{runId}/events?cursor=...
POST /api/v2/executions/{runId}/cancel
POST /api/v2/executions/{runId}/resume
POST /api/v2/approvals/{approvalId}/decisions
GET  /api/v2/executions/{runId}/artifacts
GET  /api/v2/executions/{runId}/evidence
GET  /api/v2/executions/{runId}/usage
GET  /api/v2/executions/{runId}/cost
```

Existing `/api/v1` routes and Product API read models remain compatibility
surfaces until a separately approved migration. No product calls Agenta,
Eigent, CAMEL, OpenClaw, Codex, or provider-native administration APIs.

**Decision:** `PARTIAL`; semantics are defined but the v2 route family is not
implemented.
