# ACS Workflow

# Development Philosophy

ACS development prioritizes:
- observability
- bounded autonomy
- execution traceability
- modularity
- governance compatibility

Avoid uncontrolled autonomous architecture.

---

# Operational Workflow

## 1. Cognitive Architecture Definition

Before implementation:
- define execution boundaries
- define permission scopes
- define orchestration responsibilities
- define telemetry requirements
- define governance implications

Avoid implementation-first orchestration systems.

---

## 2. Execution Boundary Validation

Every cognitive system must:
- expose execution visibility
- expose permission boundaries
- expose telemetry
- expose workflow state

No hidden execution is allowed.

---

## 3. Workflow Validation

Before deployment:
- validate orchestration logic
- validate workflow isolation
- validate telemetry consistency
- validate execution observability
- validate memory boundaries

---

## 4. Implementation

Implementation rules:
- isolate cognitive responsibilities
- isolate provider access
- isolate memory systems
- isolate execution permissions
- expose deterministic telemetry

---

## 5. Runtime Validation

Before merge:
- validate orchestration state
- validate memory integrity
- validate provider routing
- validate billing consistency
- validate workflow execution
