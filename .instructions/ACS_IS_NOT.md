# What ACS Is Not

# Purpose

This document prevents scope drift, regulatory risk, unrealistic expectations, and unsafe architecture.

ACS must be described and built as a risk-aware coordination layer, not as a profit promise system.

---

# ACS Is Not

- ACS is not an autonomous hedge fund.
- ACS is not a profit guarantee system.
- ACS is not a passive income product.
- ACS is not a risk-free trading product.
- ACS is not a custodian of user funds.
- ACS is not an exchange withdrawal system.
- ACS is not an unrestricted execution engine.
- ACS is not a governance bypass.
- ACS is not a replacement for user consent.
- ACS is not a replacement for exchange-side risk controls.
- ACS is not a public product before internal validation.
- ACS is not a marketing layer for APY, APR, easy money, or guaranteed returns.

---

# Required Language

Use:

- controlled experimentation
- guided automation
- risk-managed execution
- educational onboarding
- small capital testing
- operational transparency
- documented performance

Avoid:

- guaranteed gains
- passive income promises
- risk-free claims
- unrealistic APY or APR
- easy money language
- claims that imply Axodus controls or protects all outcomes

---

# Product Boundary

ACS may coordinate readiness, licensing, API safety, risk checks, guided presets, emergency stops, telemetry, receipts, and performance documentation.

ACS must not custody funds, withdraw funds, promise profit, hide risk, bypass governance, or activate trading without explicit user action and policy clearance.
